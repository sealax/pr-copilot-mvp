  2. What Is Working

  - Basic Next.js Pages Router app.
  - GitHub login via Supabase OAuth exists in pages/index.tsx.
  - OpenAI-backed PR readiness evaluation works.
  - Evaluation returns structured verdict/risk/recommendation data.
  - Generation is gated by evaluation state.
  - NO-GO generation is blocked client-side and server-side.
  - Evaluations are attempted to be saved to Supabase.
  - Generations are attempted to be saved to Supabase.
  - Logged-in users can fetch recent evaluations.
  - Clicking a recent evaluation tries to load the latest linked generation.
  - Local demo fallback now allows generation when Supabase evaluation insert fails, using a signed evaluation token.

  3. Incomplete Or Fragile

  - UI is very basic and mostly inline styles.
  - Login is minimal: no logout, no account area, no protected dashboard.
  - Usage tracking is local React state only.
  - History only fetches latest 5 evaluations.
  - Supabase persistence failures are logged but not surfaced clearly to users.
  - Evaluation and generation APIs use any/untyped request handlers.
  - No schema validation library.
  - No lint script.
  - No tests.
  - No Stripe/payment logic yet.
  - No real production onboarding or pricing state.
  - README is partly behind the code: persistence now partially exists.
  - Some unused code exists: evaluation, extractVerdict, extractRiskScore, selectedGeneration is only partly useful.

  4. Security Risks

  - Biggest issue: API routes trust user_id from the browser. A malicious client could submit another user’s ID.
  - Server uses SUPABASE_SERVICE_ROLE_KEY, which is normal for API routes, but dangerous if combined with trusted
    client-supplied user_id.
  - No server-side verification of the Supabase session/JWT in /api/evaluate or /api/generate.
  - No rate limiting on OpenAI API routes.
  - No database-backed usage cap.
  - The 5-free-pitch limit is client-side and bypassable.
  - evaluation_token fallback is signed, but currently has no expiry, nonce, or replay limit.
  - /api/evaluate returns raw: parsed, which is useful for debugging but should not be exposed in production.
  - API errors are generic to the client but detailed logs may include model output/server details.
  - No input length limits. A user can send very large prompts and drive OpenAI cost.
  - Supabase anon key is exposed client-side, which is expected, but RLS policies must be correct. I cannot verify RLS
    from this repo.

  5. Usage Tracking
  Usage tracking is currently client-side only.

  In pages/index.tsx, this line controls usage:

  const [pitchesUsed, setPitchesUsed] = useState(0);

  The app increments it after successful generation. This resets on refresh, browser change, or direct API calls. It is
  not production-safe and not tied to Supabase.
